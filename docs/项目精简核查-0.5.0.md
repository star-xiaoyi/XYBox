# XYBox 0.5.0 项目精简核查

核查日期：2026-10-01。基线：`0685cfbd0ccfd72a60fc0e34b111299c00a01502`，已发布 0.5.0，arm64-v8a 手机/平板 APK。

本次只核查，未删除或修改业务代码、资源、构建配置；仅新增本报告。未重新运行构建，使用同一基线已成功完成的正式版构建及其 R8、资源裁剪、AAR、APK 产物作交叉检查。扫描的是 Git 跟踪文件、当前工作目录（磁盘统计不含 .git）、构建配置、手机端引用及现有产物，不代表已穷尽外部片源、动态插件和全部设备的运行行为。

## 结论

可以精简，第一步应优先处理停用构建残留、重复文件和成组的旧界面代码。不能用“搜索不到调用”或“R8 删除了类”作为单独删除依据；常量内联、接口合并、Room 生成代码、XML 控件、反射与动态片源均会造成误判。

- 跟踪文件 1,305 个，文件内容共约 59.0 MiB，不包含 Git 历史、被忽略的库及构建产物。
- 当前 main/mobile 下 Java/Kotlin 源文件 380 个，扫描其相互引用，并结合 XML、Manifest 和 R8 usage.txt 筛选。
- 19 个源码文件满足“无其他当前 main/mobile 源码或 XML 的直接名称引用，且 R8 整类移除”，共 56.2 KiB。它们是候选，不是无条件删除列表。
- 115 个当前 main/mobile 文件型资源在资源裁剪记录中为不可达，共 152.7 KiB；不包括 values 文件内的独立条目。需要按资源链、同名变体和电视端共享关系复核。
- 三组完全重复的 arm64 原生库，去掉一侧副本可减少源码工作树约 11.2 MiB。APK 已经仅含一份，不能宣称安装包也缩小 11.2 MiB。
- 可再生构建目录合计约 915.7 MiB，项目 .gradle 缓存约 64.6 MiB。清理会释放本地磁盘，但下次构建会重新生成，且会丢失其中当前诊断资料与本地产物。

## 建议第一批：低风险、边界明确

| 项目 | 当前证据 | 建议 | 收益及限制 |
|---|---|---|---|
| `chaquo/` | settings.gradle 已注释 include；app 依赖也已注释；目录仅 3 个跟踪文件 | 删除停用模块及根 build.gradle 的 `com.chaquo.python apply false` 声明，清理相关过期注释 | 减少无效模块/插件配置；不是再省 8–10MB APK，Python 本就未打包 |
| `app/libs/sherpa-onnx-1.13.8.aar` | 约 47.8 MiB，本地忽略文件；fileTree 显式排除；正式 APK 无 sherpa/onnx 原生库；当前语音为云端 | 可移出项目或删除本地旧 AAR；清理无效 JNI 排除项前复核整个依赖来源 | 只释放本地空间，当前 APK 不受影响 |
| `app/src/mobile/AndroidManifest.xml` | 当前 sourceSets 只引入 mobile/java 和 mobile/res，Manifest 使用 main；代码地图也明确该文件不合并 | 删除不生效副本，保留 main 的真实注册 | 避免今后修改错文件；先确认没有外部脚本依赖此路径 |
| `init.gradle` | 当前仓库构建入口未发现引用；根目录该命名不会被 Gradle 自动执行 | 可列入移除候选；先核对个人 IDE/外部命令有无 `-I` 引用 | 减少过期镜像/本地配置入口，不能仅凭仓库搜索断言外部绝不用 |
| 构建/文档过期说明 | app/build.gradle 版本注释仍为旧算法；README 手动 Gradle 构建命令与项目规则冲突 | 精简时同步修正文档与注释 | 降低误操作，不改变功能 |

注意：`PyLoader.java` 仍被 `BaseLoader` 调用，为 .py 片源返回 SpiderNull。删除 chaquo 模块不等于可直接删除 PyLoader；保留当前降级语义，若要合并该类需单独验证。

## 建议第二批：原生库去重

下面每组已核对 SHA-256 一致；现有模块 release AAR 也包含对应 arm64 库，当前 APK 内库内容与源码完全一致。建议保留库所属模块的一份，删除 app 中重复副本，然后做完整构建和包内逐个比对。

| 可去掉的 app 副本 | 保留来源 | 字节数 |
|---|---|---:|
| `app/src/main/jniLibs/arm64-v8a/libjpa.so` | `jianpian/src/main/jniLibs/arm64-v8a/libjpa.so` | 5,288,528 |
| `app/src/main/jniLibs/arm64-v8a/libxl_stat.so` | `thunder/src/main/jniLibs/arm64-v8a/libxl_stat.so` | 837,976 |
| `app/src/main/jniLibs/arm64-v8a/libxl_thunder_sdk.so` | `thunder/src/main/jniLibs/arm64-v8a/libxl_thunder_sdk.so` | 5,607,344 |

其他 app/jniLibs 下的播放器、Cronet、QuickJS 等库不能因名字与依赖相似就删。本次只确认以上三组源码副本内容一致。

删除跟踪的大文件只减小当前检出目录；旧文件仍在 Git 历史中。本轮不需要重写历史，也不应为缩仓库强推历史。

## 建议第三批：旧界面与资源成组清理

源码候选和资源候选完整清单见附录。旧类对应的布局、子控件、回调要成组追踪，不能一刀切。

- `SpeedTest`、旧下载设置/同步弹窗、旧 AboutDialog 等已无当前手机端直接入口，可先从这些明确孤立的入口检查。
- `DohCallback` 虽无当前手机端引用，但仍被 leanback 的设置页及 DohDialog 使用。现行规则保留电视端，应保留或迁移到电视端源集，不能直接删除共享接口。
- `CustomSwitch` 在 Java 调用搜索中看似无引用，但多个 XML 仍引用它；必须先清掉已废弃 XML 链，不能单独删控件。
- `Constant`、Room DAO、若干回调也出现在 R8 整类移除结果里，但仍有真实引用或生成代码需求，已从“无直接引用候选”中排除。
- 资源裁剪已自动处理多数无用资源，删这些源文件主要改善可维护性，不能保证明显缩小 APK。
- 删除限定符资源变体后，按项目规则执行 `./build.sh --clean`，避免合并缓存继续保留旧资源。

## 实施顺序与不变性检查

1. 以 0.5.0 的 tag 和 APK 为基准。先处理停用模块/配置及三组原生库副本，不同时调整功能。
2. 每批按 `./build.sh --check` 检查；通过后完整 release 构建。资源变体删除执行 `./build.sh --clean`，不使用 debug。
3. 对比前后合并 Manifest、权限/组件、ABI 与原生库哈希、assets 清单、关键资源、包签名及 Room schema；不得出现不在预期清单中的变化。
4. 旧界面按入口逐组移除，重新检查剩余源码/布局引用和 R8 记录。不要照着附录整批删。
5. 真机覆盖：AI 文字/语音/历史，普通搜索与点播、直播，Exo/IJK 播放与字幕弹幕，磁力/迅雷/荐片等特殊链接、JS/JAR 片源，投屏、下载、WebDAV、旧数据升级，手机/平板和深浅色主题。
6. 执行时另定下一版 beta 号；未获真机验收不提交代码、不发布正式版。本次对 0.5.0 的提交授权不延伸为今后精简的自动提交授权。

单靠静态核查不能承诺所有动态片源行为百分之百不变；可以用保守范围、分批变更和包内容/真机回归把“不改变现有功能”落实为验收条件。
