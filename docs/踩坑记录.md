# 踩坑记录

按主题分类。AGENTS.md 只留铁律，细节在这里查。

## 混淆与打包

**Gson + R8**：release 包中任何被 Gson 反序列化的内部数据类（如 `WebDAVSyncManager$SyncEnvelope`）必须在 `proguard-rules.pro` 里 keep，否则字段名和泛型被擦除，列表元素退化成 `LinkedTreeMap`，强转 Bean 时 ClassCastException。`bean` 包已整体 keep，`utils` 包里的同步类要手动加规则。验证方法：查 `app/build/outputs/mapping/release/mapping.txt`。

**真机验证必须用 release 包**：混淆相关问题 debug 包永远复现不了。且 debug 用的是 Android 默认签名，装不到已有 release 包的机器上（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`，只能卸载重装、本地数据全丢）。

**测试连接成功 ≠ 同步逻辑正常**：WebDAV 测试连接不经过 Gson 解析，同步才经过。排查同步问题要直接看同步路径。

**删除资源限定符变体后必须 clean 重建**：删掉 `layout-sw600dp/xxx.xml` 这类变体文件后，Gradle 的资源增量合并**不会**把它从 `app/build/intermediates/merged-not-compiled-resources/` 里清掉，陈旧副本会继续被打进 APK。表现极具迷惑性：源码只剩一份布局，手机怎么测都正常，但平板（sw>=600dp）运行时仍命中幽灵变体，`ViewBinding.inflate` 报 `Missing required view with ID: xxx`。v0.2.2 删了源文件却没 clean，v0.2.3 仍在崩，直到 v0.2.4 执行 clean 才真正生效。验证方法：`find app/build -name "<布局名>*.xml"`，确认没有多余限定符目录。用 `./build.sh --clean`。

## 应用内更新

**发预发布版用户收不到更新**：GitHub 的 `/releases/latest` 接口按设计跳过所有 prerelease。v0.3.2-beta 发出去手机检查不到更新就是这个原因。现在 release 通道（点击版本号）查 `/releases/latest` 只看正式版，dev 通道（**长按**版本号）查 `/releases` 列表含 beta。发 beta 后要提醒用户长按。

**资产命名**：`Updater.findApk` 要求文件名同时含 `mode`（mobile）和 `abi`（`arm64` / `arm64-v8a`），例如 `XYBox-mobile-arm64-v8a.apk`。不含 abi 时有「唯一 apk」兜底，但不要依赖。

**版本号比较**：tag 必须和 `versionName` 逐字一致（含 `-betaN` 后缀）。`Updater.compare` 先比主体数字，主体相同时正式版高于同主体的任何 beta，两个 beta 比后缀序号。versionCode 规则见 [操作手册](操作手册.md)：正式版尾数固定 9，保证能从 beta 覆盖安装到正式版。

**大文件上传会卡超时**：`gh release create` 传 36MB 的 APK 常常超过 5 分钟工具超时，release 会卡在 Draft 且无资产。补救：`gh release upload <tag> <apk> --clobber` 后 `gh release edit <tag> --draft=false --prerelease`。`build.sh --publish` 已处理，手工发布时上传步骤建议后台跑。

## 布局与资源

**`configChanges` 会让布局资源变体失效**：`VideoActivity` 声明了 `configChanges="orientation|screenSize"`，旋转**不重建 Activity、布局不会重新 inflate**。详情页基本都是竖屏进入，所以横屏全屏用的仍是 `layout/` 那份，`layout-land/` 几乎走不到。v0.3.2-beta2 只改了 `layout/view_control_vod.xml` 的顶栏顺序，结果横屏也跟着变了。**凡是随方向变化的布局差异，在这个页面只能运行时改（搬 View、改 LayoutParams），靠 `layout-land/` 是无效的**。搬 View 时两份布局要同步加同名 id——ViewBinding 对布局变体是同一个类，id 不一致直接 `Missing required view` 崩溃。

**`@mipmap/ic_launcher` 是两份资源**：`mipmap-anydpi-v26/ic_launcher.xml` 是自适应图标（背景走 `@color/launcher_background`），`mipmap-<density>/ic_launcher.webp` 是传统栅格图、**白底烤在图片里**。取到哪份由系统资源匹配决定。v0.3.2-beta1 改了颜色后桌面变黑底、通知栏仍是白底就是这个原因。**代码里要画应用图标，用自绘的 `@drawable/ic_notify_art`（同色背景 + 20% 内缩前景），不要引 `@mipmap/ic_launcher`**。另注意 `layer-list` 的 item 边距只接受 dimension，不认 `20%`。

**桌面图标不随系统深浅色切换**：桌面图标由 Launcher 进程加载并缓存，缓存在安装/更新那一刻按当时配置生成，之后切换深浅色绝大多数 Launcher 不会重建。所以给 `launcher_background` 配 `values-night` 变体只会造成「深色模式装的永远黑底」以及桌面与通知栏各取一值。**统一固定一个色值**（当前 `#222222`）。真要跟随主题只有系统的「主题图标」（`monochrome`）一条路，配色由壁纸决定，不归我们控制。

**透明系统栏会招来系统的对比度保护条**：API 29 起只要导航栏/状态栏是透明或半透明，系统会自动垫一层 scrim（小白条下那条长方形）。关掉要两处一起：主题里 `enforceNavigationBarContrast` / `enforceStatusBarContrast`（见 `values-v29/styles.xml`），以及 `BaseActivity`、`HomeActivity` 运行时设色处的 `setNavigationBarContrastEnforced(false)`。注意资源限定符是**整个 style 覆盖不是逐条合并**，写 `values-v29/AppTheme` 时必须把 `values-v27` 里的项一并重写，漏写等于在 API 29+ 上丢了刘海屏配置。

## 触摸与坐标

**窗口坐标 vs 屏幕坐标**：`MotionEvent.getRawX/getRawY` 是屏幕坐标（含窗口偏移），`ResUtil.getScreenWidth/Height` 是窗口自身尺寸（不含偏移）。全屏时偏移为 0 两者重合，分屏/小窗时不重合。v0.3.1 的手势边缘判定混用了这两者，导致分屏下整个播放区被误判成系统手势边缘、触摸全灭。**凡是涉及触摸坐标的判断，一律用窗口内坐标（`getX` + `getLocationInWindow`），不碰 raw 坐标**；播放器左右分区要用视频 View 的实际宽度，不是屏幕宽度。改完必须在分屏和小窗下真机回归。

## 环境

**安装签名冲突**：`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 说明手机上旧包签名不同，需先卸载（会清本地数据，WebDAV 云端数据不受影响）。

**沙箱拦截**：gradle 命令可能因无法写 `D:\dev\gradle-cache\daemon` 日志被拦，报 `TRAE Sandbox Error`，用需要用户授权的方式重跑。
