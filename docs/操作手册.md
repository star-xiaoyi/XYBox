# XYBox 编译与发布操作手册

面向本人手动操作，在仓库根目录 `D:\projects\XYBox` 执行。

## 零、一条命令搞定（推荐）

日常改完代码要发测试包，用 `build.sh` 就够了，它把改版本号、算 versionCode、编译、发布串成一步。**在 Git Bash 里执行**（不是 PowerShell）：

```bash
./build.sh 0.3.2-beta4 --publish
```

| 命令 | 作用 |
|---|---|
| `./build.sh` | 用当前版本号编译 release 包 |
| `./build.sh 0.3.2-beta4` | 改成该版本号再编译，versionCode 自动算 |
| `./build.sh 0.3.2-beta4 --publish` | 编译后发到 GitHub（beta 自动带 `--prerelease`） |
| `./build.sh 0.3.2 --publish -m "更新说明"` | 发正式版并写发布说明 |
| `./build.sh --clean` | 先 clean 再编译 |

脚本会挡掉几类翻车：版本号格式不对、versionCode 倒退（手机装不上）、工作区有未提交改动就发包。上传也拆成了「建草稿 → 传资产 → 转正式」三步，36MB 的包传到一半断了可以单步重跑，不会留下一个没资产的 Draft。

**什么时候必须加 `--clean`**：删过 `layout-land/`、`values-night/` 这类资源限定符变体之后。Gradle 的增量资源合并不会清掉已删的变体，陈旧副本会继续被打进 APK。

下面是手动分步的做法，脚本出问题时对照排查用。全部命令在 **PowerShell** 里执行。

---

## 一、准备（只需确认一次）

编译环境不在默认位置，全在 `D:\dev`：

| 用途 | 路径 |
|---|---|
| JDK 17 | `D:\dev\runtimes\jdk-17` |
| Android SDK | `D:\dev\tools\android-sdk`（已写进 `local.properties`） |
| Gradle 缓存 | `D:\dev\gradle-cache` |
| adb | `D:\dev\tools\android-sdk\platform-tools\adb.exe` |

签名文件在 `keystore/release.jks`，密码已写死在 `app/build.gradle` 里，不用额外配置。

发布要用 GitHub CLI，确认已登录：

```powershell
gh auth status
```

没登录就 `gh auth login`，选 GitHub.com → HTTPS → 浏览器授权。

---

## 二、改版本号

编译前先改 `app/build.gradle` 的 `versionCode` / `versionName`。

### 命名规则

一个版本的生命周期：先发若干个 beta 给自己测，测通过了才发同号的正式版。

| 阶段 | versionName | versionCode |
|---|---|---|
| 第 1 个测试包 | `0.3.4-beta1` | 3041 |
| 第 2 个测试包 | `0.3.4-beta2` | 3042 |
| … | … | … |
| 测好了，发正式版 | `0.3.4` | 3049 |
| 下一轮 | `0.3.5-beta1` | 3051 |

`versionCode` 算法：**(major×1000 + minor×100 + patch) × 10 + 尾数**，beta 尾数用序号 N，正式版尾数固定用 **9**。

- 尾数 9 保证正式版的 code 一定高于自己所有的 beta，**否则从 beta2 装正式版会被系统当成降级拒掉**。
- 一个版本最多 8 个 beta（beta1~beta8），够用。

`versionName` 里的 `-beta1` 会原样显示在设置页版本号处，你一眼就能看出手里装的是不是测试包。

### 更新链路

`Updater.compare` 按这个规则判断新旧：先比主体数字，主体相同时**正式版永远高于同主体的任何 beta**，两个 beta 之间比后缀序号。所以下面三条路都通：

```
0.3.4-beta1  →  0.3.4-beta2  →  0.3.4（正式）  →  0.3.5-beta1
```

不会出现「beta2 装了以后正式版反而提示已是最新」的情况。

## 三、编译

```powershell
$env:JAVA_HOME='D:\dev\runtimes\jdk-17'; $env:GRADLE_USER_HOME='D:\dev\gradle-cache'; .\gradlew.bat assembleRelease --no-daemon
```

看到 `BUILD SUCCESSFUL` 即成功，产物在：

```
app\build\outputs\apk\release\XYBox-release.apk
```

约 36MB（release 开了 minify + shrinkResources）。

确认产物是刚生成的（别把上次的旧包发出去）：

```powershell
Get-ChildItem app\build\outputs\apk\release\XYBox-release.apk | Select-Object Name,Length,LastWriteTime
```

**什么时候必须先 clean**：删过 `layout-sw600dp/` 这类资源限定符变体文件之后。Gradle 的增量资源合并不会清掉旧副本，不 clean 会打进 APK 里，手机正常但平板崩。

```powershell
$env:JAVA_HOME='D:\dev\runtimes\jdk-17'; $env:GRADLE_USER_HOME='D:\dev\gradle-cache'; .\gradlew.bat clean assembleRelease --no-daemon
```

## 四、装到手机自测（可选）

```powershell
D:\dev\tools\android-sdk\platform-tools\adb.exe install -r app\build\outputs\apk\release\XYBox-release.apk
```

报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` = 手机上的旧包签名不同，先卸载再装（会清本地数据，WebDAV 云端数据不受影响）：

```powershell
D:\dev\tools\android-sdk\platform-tools\adb.exe uninstall com.xybox.app
```

## 五、发布到 GitHub

### 1. APK 必须改名（关键，改错就更新不了）

应用内更新挑安装包的规则见 `Updater.findApk`：文件名要同时包含 `mobile` 和 `arm64-v8a`。

```powershell
Copy-Item app\build\outputs\apk\release\XYBox-release.apk app\build\outputs\apk\release\XYBox-mobile-arm64-v8a.apk -Force
```

### 2. 提交推送

```powershell
git add -A
git commit -m "fix(xxx): 一句话说清改了什么" -m "为什么这么改、原来为什么错"
git push
```

注意：PowerShell 不支持 heredoc，多段提交信息用多个 `-m`。

### 3. 建 release

**正式版**（所有人点「检查更新」都能收到）：

```powershell
gh release create v0.3.3 "app\build\outputs\apk\release\XYBox-mobile-arm64-v8a.apk" --title "v0.3.3" --notes "本次更新内容"
```

**beta 版**（只有 dev 通道能收到）：

```powershell
gh release create v0.3.4-beta1 "app\build\outputs\apk\release\XYBox-mobile-arm64-v8a.apk" --prerelease --title "v0.3.4-beta1" --notes "本次更新内容"
```

tag 必须和 `versionName` 完全一致（带 `-beta1`），否则 App 比较版本时对不上。

发完核对一下：

```powershell
gh release view v0.3.3 --json tagName,isPrerelease,isLatest,assets --jq '{tag:.tagName,pre:.isPrerelease,latest:.isLatest,assets:[.assets[].name]}'
```

## 六、手机上怎么收更新

App 里两个入口，走**不同**的通道：

| 操作 | 通道 | 能看到什么 |
|---|---|---|
| 设置页 **点击**版本号 | release | 只有正式版（GitHub `/releases/latest` 接口，按设计跳过 prerelease） |
| 设置页 **长按**版本号 | dev | 正式版 + beta（`/releases` 列表接口，取最新一条，跳过草稿） |

所以：**发了 beta 之后要长按版本号才能更新到**，点击是收不到的。

---

## 七、更新不到时按这个顺序查

1. **发的是 beta 吗？** 是的话必须长按版本号。这是最常见的原因。
2. **版本号真的变大了吗？** `Updater.compare` 先比主体数字，主体相同时正式版高于任何 beta，两个 beta 比后缀序号。`0.3.4-beta1` → `0.3.4` 算有更新，`0.3.4` → `0.3.4-beta2` 不算（不会让你往回降）。
3. **tag 和 versionName 一致吗？** tag 要 `v0.3.4-beta1`（开头的 `v` 会被自动去掉），和 `app/build.gradle` 里的 `versionName` 逐字对应。
4. **资产名对吗？** 必须含 `mobile` 和 `arm64-v8a`。不含 abi 时会退回「唯一的那个 apk」兜底，但别依赖这个。
5. **提示「API请求次数已达上限」** = GitHub 匿名限流（每 IP 每小时 60 次），换网络或等一小时。
6. **release 是草稿状态吗？** 草稿的资产没公开，下不下来，dev 通道会主动跳过。

## 八、一次完整发布的命令清单

```powershell
# 1 改 app/build.gradle 的 versionCode / versionName

# 2 编译
$env:JAVA_HOME='D:\dev\runtimes\jdk-17'; $env:GRADLE_USER_HOME='D:\dev\gradle-cache'; .\gradlew.bat assembleRelease --no-daemon

# 3 改名
Copy-Item app\build\outputs\apk\release\XYBox-release.apk app\build\outputs\apk\release\XYBox-mobile-arm64-v8a.apk -Force

# 4 提交
git add -A; git commit -m "描述"; git push

# 5 发布（正式版；发 beta 就加 --prerelease 且 tag 带 -beta）
gh release create v0.3.3 "app\build\outputs\apk\release\XYBox-mobile-arm64-v8a.apk" --title "v0.3.3" --notes "更新内容"

# 6 手机上：设置页点击版本号（beta 则长按）
```
