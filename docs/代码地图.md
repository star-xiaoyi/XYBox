# 代码地图

## 源码结构

`app/build.gradle` 的 sourceSets 把 **mobile 目录作为 java/res 源码目录**合并进构建：

```
app/src/main/     → 主源码 + 主 AndroidManifest（实际生效的 manifest）
app/src/mobile/   → 手机端 UI（java + res，通过 sourceSets 合并）
app/src/leanback/ → 电视端（当前不构建）
```

**`app/src/mobile/AndroidManifest.xml` 不参与构建合并**——新增 Activity/Service 必须注册到 `app/src/main/AndroidManifest.xml`，否则运行时 `ActivityNotFoundException`。

只有 `release` 一个 buildType（`debug` 是 Gradle 隐式提供的），**没有 productFlavors**。上游 XMBOX 的 `assembleMobileArm64_v8aRelease` 那套 flavor 任务在本项目里早已不存在，见到引用它们的脚本或文档一律视为过时。

手机端已移除直播模块。直播配置、频道与节目单解析、直播 ViewModel 和 TVBus 提取器保留在 `app/src/leanback/java/`，不参与当前手机包编译。手机端的 `bean/Live.java` 只保留旧数据库和备份使用的四个字段，不包含播放逻辑，数据库结构无需迁移。

应用启动时由 `utils/UpdatePackages.java` 清理 `files/updates/` 内已安装版本及更早版本的更新 APK，保留待安装的新版本。`utils/StorageDiagnostics.java` 在导出运行日志时生成目录占用报告。

点播配置由 api/config/VodConfig.java 汇总所有启用配置，站点 key 使用 search/SourceIdentity.java 的地址哈希命名空间，避免不同接口的同名站点冲突；解析器、JAR 和 flags 按所属配置查找，禁止依赖全局最近使用的配置。配置及单站点停用开关独立保存，停用后不参与目录和自动选源。

search/QualityCatalog.java / QualityProbe.java 随影片静默核实同片同集线路，与菜单开关无关；线程池上限六个，手机实际预算为 0～4 个，按配置和站点轮转，缓冲不足或暂停时取消超预算任务并保留待重试队列。任务提交时就登记有界超时；第三方 spider 忽略中断时废弃被占住的工作池并在新池继续后续站点，旧回调因任务身份失效不能写回。单次媒体读取最多 35 秒，容器识别后仍至少保留 128 KiB 的有界吞吐采样，避免用 32 KiB CDN 突发误判可持续速度。TS 读取器明确使用 HLS 模式，支持 AES-128、MP4 尾部 moov 和纯地址代理响应；通过实际容器核实分辨率，站点“蓝光”和 HLS RESOLUTION 标注不算核实。QualitySelection.java 先比较实测吞吐量对码率的余量，再比较画质；健康播放期间后台结果只补候选。有待处理的播放故障时，新增核实结果交给同一个恢复入口。

bean/QualityMemory.java / search/QualityCache.java 在 files/quality-records 保存影片候选、按剧集核实的尺寸、搜索完成记录及失败冷却，文件读写在专用线程串行进行，跨页面和进程恢复；不保存视频数据和已解析的临时播放 URL。单片最多 512 KiB、整体最多 32 MiB/160 部片，淘汰旧剧集时同步清除其核实标记。配置地址、站点 API/JAR/扩展及解析器变化只失效其所属站点；禁用站点过滤已有选项。手动选择旧记录时仅刷新所选线路的播放地址，继续按真实媒体尺寸映射变体。历史续看先用保存的源、集数和进度，失败后才换备用。

search/SearchTask.java 普通搜索按 24 个请求/6 并发分批；播放页后台按 64 个请求/2 并发分批持续查找，跟随播放缓冲预算暂停、恢复。播放恢复先让所有站点搜索主标题第一页，再统一尝试第二页及最多两个片名别名，不能让前几个站点的深翻页饿死后面的站点；明确坏源时切为前台六并发。批次超时会隔离已卡死的站点、轮换工作池并继续尚未启动的请求，迟到回调失效。SiteHealth.java 按配置轮转，同一配置内优先手动标记、近期成功及耗时较小的站点；只搜索当前影片尚未查过或已到重试时间的站点，未实际执行的请求不计已搜索。HTTP 非成功响应按失败而非空结果记录。SourceDiscovery.java 从入口标题、括号/斜杠别名及豆瓣原名生成受限查询计划；查询计划变化会重新开放站点缓存。进入播放器即取消搜索页任务，避免它与播放页重复竞争。详情元信息按作品名和年份固定，Douban.java 依次使用移动 JSON、移动网页和旧联想接口匹配，并保留 title、original_title、aka 给片源识别。条目 JSON 缺年份、地区或类型时补读已核实条目编号的网页，card_subtitle 也可补齐结构化字段；无评分不影响其他资料。部分资料不作为完整缓存，30 秒后最多重试一次且保留已显示内容。片源资料采用独立快照，只从匹配的来源补缺项；历史与搜索入口自带的年份和分类也参与回退。DoubanDetail / DetailMetadata 分别记录返回字段和最终显示字段、标签区域尺寸。

崩溃页复制、分享和文件保存包含完整调用栈与环境。AppLog 在 CAOC 处理前同步刷新未捕获异常到运行日志，崩溃内容不经过普通消息截断。

player/PreviewPlayer.java 恢复 beta5 之前的进度预览：使用原有系统解码选择，控制栏显示且主播放器至少缓冲 15 秒（或已缓冲到片尾）时预热；拖动和松手按目标毫秒定位，松手后保留 10 秒供连续拖动复用。撤回软件解码限定、Surface 800 ms 限制和额外生命周期禁用，不再因 TextureView 刚显示而拒绝首次预览。预览失败只隐藏预览，不触发主播放器换源或关闭页面。

2026-10-08 两份系统原生堆栈均指向后台 SearchTask → LiveAiDouYuGuard 构造 → DexNative.getSpider 的空对象 JNI SIGABRT，不是预览解码器。api/loader/SourcePluginPolicy.java 只隔离已证实崩溃的 csp_LiveAiDouYuGuard，站点不参加搜索/自动换源，JarLoader 在构造之前再次保护；不删除导入配置或按 Live 名称大范围禁用其他插件。JarLoader 等 Init 成功后才发布加载器，失败不进入构造；不同 JAR 的加载互不阻塞，同站点创建去重，而同一 JAR 内不同站点仍能独立初始化。scripts/JarLoaderCheck.java 使用 JVM 替身执行实际 JarLoader 并验证这些并发路径，不运行第三方 native 代码。

api/loader/RemoteSpider.java / SourceBridge.java 与 service/SourceService.java 把源 JAR、JS、JSON/Mix 解析器和本地代理执行统一放到私有 :sources 进程；主进程不加载第三方 dex，HTTP/XML 源与播放器仍在主进程。主 Manifest 中 QuickJS Provider 也移到 :sources。App 的源进程分支只初始化网络和独立日志，不启动云同步、更新清理、崩溃 Activity 或播放通知。RPC 请求与响应均用可靠文件描述符管道传输，有界 JSON 帧上限 8 MiB，媒体正文流式转发而非装进 Binder；保留代理的 jarKey、JS siteKey、Range、状态、响应头与固定长度。主进程代理端口、配置中的请求头/域名映射/代理域名和用户代理/DoH 同步到源进程，解析器的优先顺序用条目数组保留。读取使用 100 ms poll 检查中断，控制请求/媒体无数据读取上限 35 秒，不对持续有数据的整部影片设置总时限；取消传播到源任务，源工作线程数量有上限。死亡通知作废连接，后续 RPC 使用重新绑定的服务。此为崩溃隔离，不是权限沙箱；同一源进程内其他在途请求/代理可能一起失败，需要现有播放器恢复逻辑继续处理。

api/loader/SourceUnavailableException.java 把源进程不可用（重连超时、绑定失败、池满拒绝、配置换代过期）与站点自身失败分开：前者不写入 SiteHealth 冷却，RemoteSpider 在重连后透明重试一次。SourceService 统计已取消但 20 秒仍未结束的卡死任务，达到 4 个就主动退出，由系统重启干净的源进程。player/PlaybackPolicy.isLocalProxyUrl 识别 127.0.0.1 代理地址：代理流中断按原地重连处理，不再直接换源；utils/DecodeGuard.java 在检测到主进程解码器类原生崩溃后，对该影片的下一次播放临时切换软解一次，不改用户设置。VideoActivity 的播放快照补记用户暂停状态，重建恢复后不强制开播。WebView 数据目录锁（crbug.com/558377）由主进程侧解决：只有主进程调用 setDataDirectorySuffix("main")，源进程保持系统默认目录（插件环境与隔离前一致；部分 *Guard 插件会因进程里出现 Chromium 类而拒绝装载内部爬虫）；CustomWebView / ParseJob 的创建失败转为解析失败，不再崩溃（API 28 以下无此 API，靠该兜底降级）。PlaybackPolicy 的起播超时区分"有进展"：嗅探仍在进行或媒体缓冲持续增长时宽限延长到 45 秒（STARTUP_PATIENT_MS），完全没进展仍按 12 秒换源；VideoActivity 用 Players.isParsing 与缓冲增长判定。ToastFilter 增加 Notify 显式可信标记（runTrusted）：混淆后的 lambda 类名使类名匹配失效，自家提示曾被当外部弹窗拦掉。AppLog.clear 连同 files/source-logs（源进程日志）一起删除，日志界面的大小摘要和导出都以 exportLogFiles 为准；此前只清主进程目录，界面上会留下几百 KB 的“残留”。Players 把原地重连的延迟 prepare 做成可撤销的 prepareRetry：reset/stop/clear/release/setMediaItem 都会撤掉它，否则换源后旧媒体项会在新会话里补报一次清单错误（日志里的 "3002,null"）；onPlayerError 在没有当前媒体地址时直接忽略。VideoActivity.setCandidateDetail 在自动恢复（非手动）的候选校验返回时，若当前源在校验期间已出画面（mLastFrameAt >= mDetailRequestedAt）就放弃切换并记 action=keep-recovered；recoverPlayback 的两条候选路径都过滤掉仍在失败冷却中的路线。换源面板在测速进行中给按钮和未测来源显示"测速中…"。JarLoader.download 只在响应是 zip/dex 时才覆盖缓存：OkHttp.bytes 不看状态码，反爬页面或空响应曾让一批站点持续报 "Expected valid zip or dex file"，缓存里原本可用的 jar 现在会保留并记一条 JarLoader: non-jar response。SourceService 对取消导致的 InterruptedException 不再记 SourceFailure。ProfileFragment 的 PRESET_SOURCES 是彩蛋：添加配置时地址栏填 XY，补齐作者自用的五个点播源（地址写法与设备上保存的一致，站点 key 才能对上历史记录）。

VideoActivity 移除片名搜索固定 10 秒的空状态计时器，DetailLoadPolicy.canShowEmpty 仅在配置/搜索/后续批次/候选详情均结束后允许报空；加载区显示当前阶段与实际检查站点数。候选使用独立 SiteViewModel 预检，同片同集、有效线路与地址通过后才更改来源并停止旧播放器；空详情/空线路拒绝时保留已有播放器与选集，拖动期间延后提交。SourceDetailPolicy 与 EpisodeSelection 共享同集规则，QualityCatalog.match 委托同一实现。SiteHealth 将真正请求/初始化失败与成功空搜索分开，按站点 API/JAR/ext 修订记录一分钟冷却，取消不惩罚站点；泛称“国产//影片”不再被认作电影而排除同名动漫。

源进程日志写入 files/source-logs，主进程导出包含两边轮转文件；进程死亡后主进程补读系统退出原因及 tombstone。scripts/SourceIsolationCheck.java 使用实际 Bridge/Service/BaseLoader/RemoteSpider 与 Android JVM 替身验证 RPC 参数、超过 Binder 限制的控制帧、2 MiB 媒体转发、代理头/Range/jarKey、解析优先级、取消、死亡后重连及空线路预检；另起真实 JVM 子进程测试突然退出后的 EOF 与替换进程。它不替代 Android Binder、JS/JNI 或真机 native crash 验收。

AppLog 在 Android 12+ 进程重启后读取系统 ApplicationExitInfo 的原生 tombstone；utils/NativeCrashTrace.java 按 AOSP protobuf 字段提取信号、abort 信息、原因、寄存器和所有可用线程/栈帧，不以普通日志长度截断。输入上限 4 MiB，跳过原始内存、文件描述符和 logcat 数据；系统未保留或格式异常时明确记录。原生堆栈去重标记与短退出记录独立，升级后仍可尝试补读先前仅有 NATIVE_CRASH 摘要的记录。

运行日志页的“保存 TXT”通过系统文档选择器选择文件名和位置，导出与分享共用 AppLog 的完整快照，含设备、权限、存储诊断和全部轮转日志；末尾“日志导出结束”用于确认文本没有被外部剪贴板截断。保存只使用所选文档的 URI 授权，不申请公共存储权限。VideoActivity 的 FilePermission / VideoDetail 日志记录权限变化、配置等待、空详情及手动刷新。

search/DetailLoadPolicy.java 在联网历史入口遇到源配置仍在加载时，最多等待 12 秒；VideoActivity 随配置事件和短间隔检查自动重新取详情。只有片名的发现/聚合搜索入口也先走配置检查，没有可用站点时等待初始化结束（超时由各配置请求负责），就绪后直接搜索而不是走空站点详情；元信息回调也不能提前创建零站点任务。VodConfig.ensureInitialized() 区分进程内尚未初始化、正在加载和已完成的空目录，播放页可直接触发冷启动初始化，不再依赖先进入首页；已缓存剧集不等待目录，离线入口保留原有播放路径，缺失或停用的源进入已有备用源搜索。

VideoActivity 的实例状态保存当前来源、影片、账号、剧集和实际播放进度；系统直接重建播放页时恢复该快照，其他账号不复用。search/ForegroundSyncPolicy.java 把播放页等待云端进度的时间限制为 8 秒，超时先继续本机进度，云同步仍继续；离开页面、同步结束和销毁时清除等待回调，用户暂停后同步完成不能强制续播。PlaybackResume 日志记录状态保存/恢复、配置就绪及同步等待/超时/完成。

数据库 40 为历史增加稳定 filmId 和 sourceKeys 来源别名；数据库 41 增加每部影片的 qualityHeight，0 表示自动，正数表示最后手动选择的清晰度档位。39→40 与 40→41 都只新增列，旧账号、集数、进度和来源主键保留。search/FilmIdentity.java / HistoryIdentity.java 先用稳定作品及已确认的来源关联，再用片名、版本、年份和类型兜底；剧集单集时长不定义作品。缺年份的旧条目不能把明确不同的翻拍合为一片。尚无 filmId 的重复记录首次优先恢复更后集数，已统一的记录按最新观看时间更新。首次合并前保存 files/history-before-film-id-账号哈希.json；本地和 WebDAV 共用合并规则，云端先处理删除墓碑再合并作品。历史入口使用 VideoActivity.resume()；收藏按原 cid 解析站点。

search/EpisodeKey.java 统一数字、中文数字和普通英文集名，并保留明确季数；不以来源列表序号替代集数，缺集时查找其他来源。EpisodeCoverage.java 只把可识别的不同数字集名作为完整度证据，忽略预告和重复集名；日期、标题式集名得到“未知”而不是“零集”。已知总集数仍用于排序和诊断，但只要备用线路明确匹配当前语义集，就不能被旧下限或异常占位列表拦截；不匹配当前集的缩水数字列表仍被过滤。历史 episodeCount 不再直接建立硬下限。电影与本地缓存保留自己的入口。VideoActivity 从搜索、历史及其他入口固定作品元信息，换源携带同集和当前时间，详情页只保留选集。换源只显示在全屏底部的倍速右侧，非全屏仅保留进度控制行。换源面板按实际节点分组，与清晰度档位面板分开；首项固定显示并勾选当前来源，另有自动查找操作、重新测速和手动候选。search/SourceSelection.java 按新鲜度、吞吐量余量和媒体首包延迟比较；采样超过两分钟标记为上次，重新测速保留旧显示并清除媒体内存缓存，快速重复点击不重启工作。QualityMemory 记录 measuredAt/latencyMs 和实际完整集数，播放器核实分辨率不会更新网络采样时间。SourceChoice / SourceProbe / PlayCatalog 日志记录来源、节点、集数下限和测量依据。

search/CandidateRefreshPolicy.java 统一有限复用和失败冷却：成功媒体探测两分钟、成功搜索五分钟、失败一分钟；旧缓存的 Long.MAX_VALUE 成功标记不再形成永久排除，旧半小时失败等待缩短到一分钟。QualityMemory 版本 3 兼容读取版本 1/2，保留候选与旧采样，并清除旧版可能写入的永久异常集数下限。配置修订变化只作废该站点的验证数据，不丢掉候选身份；配置后续可用时重新恢复候选。维护器每 30 秒把到期且已完成的探测重新入队，并重新搜索到期站点，不反复重置尚未完成的队列；搜索和测速仍服从缓冲预算，正常播放不会被后台结果切换。QualityProbe.Measurement 同时保存媒体结果和实际采样时间，地址缓存复用不更新时间戳；暂停恢复也必须重新请求已过期的采样。HTTP 无效地址直接交给换源，网络中断、限流和服务端暂时故障仍有限重连；全局断网不惩罚当前站点，网络验证恢复后重新解析当前集并续接原进度。

历史页和“我的”页先展示本地记录；本地为空且前台或联网同步未完成时显示加载状态，同步结束后才显示空提示。App 在 Activity 初始化前设置前台待同步状态；WebDAVSyncManager 在所有同步的开始、结束（包括失败）发出历史刷新事件，ForegroundSyncEvent 负责结束前台等待。HistoryScreen 记录本地查询数量、账号和页面状态。

WebDAV 沿用 xybox_sync_v2.json，schema 4 新增 SyncProfile 和 sourcePreferences。昵称、头像图片数据、源开关、站点开关及手动优先级分别按修改时间合并；头像在应用私有 avatars 目录还原，不上传本机路径或本地账号 id。首次上传建立完整初始状态，按用户要求先由手机同步，再让平板恢复；两端均需升级，否则旧版会拒绝较新格式。SourcePreferences 迁移旧开关和手动优先级到对应本地账号；新账号保留默认状态。修改资料或开关触发已有防抖同步，回写时再次检查当前值以保留上传期间的本机修改。切换账号或收到开关变更时重新加载源目录，保持正常播放不重启。SiteHealth 的网络测量、失败计数和近期搜索记录仍只保存在本机。

WebDAVSyncManager.diff 的本机下载统计忽略 Config 的 Room 编号差异，云端上传比较仍保留统一编号，以免不同设备每次同步都将同一批配置误报为更新。WebDAVDelta 分开记录上传、下载的历史与配置数量，辅助核对反复更新的原因。

PermissionUtil.installAudit 在 AppLog 初始化后登记 AndroidX 权限代理，保留原始权限流程，同时记录写/读文件权限的申请栈和 SourceUiOrigin 登记的 JAR 文件名。直接调用平台 Activity.requestPermissions 的插件可能绕过该代理，此时只保留 VideoActivity 的权限结果记录，不把回调时间误当成申请方证据。

search/PlaybackSelection.java 处理详情载入时的空列表边界，EpisodeAdapter / FlagAdapter 的当前项允许为空；currentVerifiedQuality 先检查已起播和列表就绪，首次选中其他来源时日志不再访问空剧集。ui/custom/PlaybackActionLayout.java 固定 App 的底部操作控件，拒绝来源插件动态插入额外按钮，并通过 PlayerControls 记录其文字。

utils/SourceUiOrigin.java 在 JarLoader 初始化源之前登记动态类加载器，识别 spider 入口以外和混淆后的源辅助类；SourceUiGuard 保护页面、播放器和窗口内容的新增子视图，并对源直接取得的 WindowManager 静默处理新增、更新、移除。系统 Window/Dialog 初始化保留真实 WindowManagerImpl，不能对所有系统服务查询无差别返回代理。ToastFilter 补充 Toast 与通知拦截，按播放 Activity 实例维护状态。SourceUi 日志记录拦截路径、调用类与提示文字，PlayerPopup 记录 Toast/通知拦截。

search/PlaybackPolicy.java 提供起播超时、持续/重复缓冲、暂停与拖动保护、调整间隔及失败节点冷却。search/PlaybackHealth.java 单独验证视频轨、首帧和至少 750 ms 的实际进度；播放器 READY 只表示媒体已准备，不再立即记站点成功。无视频轨、无首帧、首帧后不前进以及明显短于既有时长的预告会进入同一恢复入口；暂停、拖动、缓冲与前后台切换不消耗健康判定宽限期，健康画面仍不受后台候选打扰。VideoActivity.watchPlayback 是持续监测入口，播放错误和主动选择也汇入 recoverPlayback；自动清晰度先考虑降低当前可用轨道，再寻找同集核实节点，最后在受限候选中请求新来源。失败恢复不会再次选择刚失败的同一来源，新搜索允许初始同年比较窗口，正常续看先启动保存的来源。手动清晰度按影片保存档位，历史续看从可用线路中恢复该档位，新影片保持自动。QualityPreference 日志记录读取、保存和恢复。PlaySession / PlayIdentity / PlayDecision / PlayHistory / PlayHealth / PlaySummary 关联会话及作品，记录切换原因、进度、首帧、可观看确认与卡顿统计。真机流程见 docs/自动播放测试.md。./build.sh --check 同时运行 scripts/PlaybackPolicyCheck.java 的纯 Java 规则检查；scripts/check_history_migration.py 用导出的 Room 39/40/41 结构核对迁移保留。

ProfileFragment.SourceManager 使用卡片三点菜单，长按进入批量勾选，检测结果才展开卡片；SourceEditor 测试通过才保存，含可展开的站点开关；进入站点管理或展开站点列表时自动检测地址。站点管理使用标准上下箭头；已启用站点排在前面，两组各自保留配置顺序，勾选变化立即重排已有视图并保留待保存的开关和优先级。测试、保存位于滚动区之外的固定底栏。配置弹窗由 showCentered 提供透明全窗口宿主；sourceDialogContent 把标题和关闭按钮放在同一固定行，只让内容随键盘滚动。DialogCloseButtonView.java / DialogCloseButton.kt 统一原生和 Compose 弹层的圆形关闭按钮：32dp 圆底、44dp 点击范围；其他原生标题按实际中心对齐关闭按钮。宿主外部点击取消弹窗，卡片消费内部点击。卡片三点是普通图标，SourceMenuLayout.java 计算同窗口菜单位置，菜单从坐标快照展开并绘制阴影；刷新或关闭先取消动画、移除菜单，不持有可能已移除的锚点。
